# Database schema reference

The app keeps all state in one SQLite database, `<state_dir>/workspace.sqlite3` (WAL mode), managed by
SQLAlchemy models in `backend/app/models.py` and Alembic migrations in `backend/migrations/versions/`.
Migrations run automatically at startup. This document describes every table and column; a test
(`tests/backend/test_schema_doc.py`) fails if a table or column exists that is not documented here.

## Conventions

- **Identifiers** are UUID4 strings (`VARCHAR(36)`), generated by the app. Never provider ids.
- **Timestamps** (`DATETIME`) are UTC. SQLite has no timezone type, so values are stored naive
  (e.g. `2026-11-05 14:23:32.989469`); the API re-attaches UTC and returns ISO-8601 with `Z`.
- **Text** is UTF-8. Anchor offsets (`start`, `end`) are UTF-16 code-unit offsets into the deterministic
  rendered-text model (DESIGN §10), i.e. JavaScript string indices, so they can be mapped back to DOM ranges.
- **Content hashes** (`*_sha256`) are hex SHA-256 of the exact file bytes. A version is identified by its hash,
  not by Git; Git branch/commit are recorded as metadata only.
- **Soft references**: a few columns reference other tables *without* a foreign-key constraint, either because
  the referenced row is created in the same transaction after the referencing one (`jobs.agent_message_id`,
  `messages.job_id`) or because the reference is a UI hint that must never block deletes
  (`reading_state.active_thread_id`). They are marked "(soft ref)" below.
- Nothing is ever deleted automatically except `idempotency_keys` (24 h) and `login_sessions` on logout;
  `terminals` rows are kept with `state = closed`.

## Entity overview

```
workspaces 1─┬─* documents 1─┬─* document_versions
             │               ├─1 reading_state
             │               ├─* review_marks
             │               ├─* previews ──1 jobs
             ├─* locks
             ├─* file_reviews
             ├─* reviews 1─* review_comments ──(FK) threads
             │               └─* threads 1─┬─* messages ──(soft) jobs
             │                             ├─* anchor_history
             │                             └─* jobs 1─* job_events
             └─* agent_sessions ◄── documents.default_session_id, threads.last_session_id,
                                    messages.session_id, jobs.session_id
named_workspaces 1─* terminals  (named_workspaces.folders: JSON list of workspaces.id)
login_sessions, idempotency_keys, alembic_version: standalone
```

## `workspaces` — root folders of the window

One row per wiki folder ever opened: the primary root (`workspace.root`), roots listed under `[[workspaces]]` in the
config, and folders added from the UI ("Add folder"). Every per-wiki table below is keyed by this id, which is what
isolates wikis from each other. If the primary root changes and its previous folder no longer exists on disk, the
existing row is relocated (see docs/OPERATIONS.md, "Moving or cloning").

| Column | Type | Meaning |
| --- | --- | --- |
| `id` | UUID, PK | Workspace id (sent by the browser as `X-Workspace`). |
| `root_path` | TEXT, unique | Absolute, resolved path of the wiki folder. |
| `name` | TEXT, nullable | Display name in the file tree / switcher (default: folder name). |
| `position` | INTEGER | Order in the file tree. |
| `active` | BOOLEAN | Open in the window, i.e. a folder of the current named workspace. `false` = not shown now; its data is kept and returns when the folder is shown again. |
| `created_at` | DATETIME | First seen. |

## `github_repo_wikis` — the wiki the agent uses for a repository's pull requests

Set once per repository when a pull request is first opened from **Reviews** (and changeable in the PR tab).
Discussions about a PR are attached to a hidden, read-only document of that wiki,
`.waw-github/<owner>/<repo>/<number>.md`, whose content is the PR copy the review hub writes to
`<state_dir>/snapshots/github/` (never a file in the wiki).

| Column | Type | Meaning |
| --- | --- | --- |
| `repo` | TEXT, PK | `owner/name`, lower case. |
| `workspace_id` | UUID, FK → `workspaces.id` | Wiki folder the agent works in for this repository's PRs. |
| `updated_at` | DATETIME | Last change. |

## `github_pr_drafts` — pending review comments on a pull request

Comments written in a PR tab's Files view; published to GitHub together as one review (*Finish review*), then
deleted. Kept when GitHub refuses the review.

| Column | Type | Meaning |
| --- | --- | --- |
| `id` | UUID, PK | Draft id. |
| `repo`, `number` | TEXT (owner/name, lower case), INTEGER | The pull request. |
| `path` | TEXT | File in the PR. |
| `subject` | `line` \| `file` | `file`: a comment on the whole file (`line` is 0). |
| `side`, `line` | `LEFT` (old) \| `RIGHT` (new), INTEGER | Line the comment is on (the last line of a range). |
| `start_side`, `start_line` | nullable | First line of a multi-line comment. |
| `line_text` | TEXT | The commented diff lines, for display. |
| `body` | TEXT | Comment (Markdown). |
| `created_at` | DATETIME | Written. |

## `named_workspaces` — named sets of folders (VS Code-style workspaces)

Which folders the window shows, in order. Exactly one row is `current`. "Default" (`is_default`) is created on the
first start with this table from the folders open until then, always contains the folders of config.toml, and
cannot be deleted. Folder data belongs to `workspaces`, so a folder in two named workspaces shares its data.

| Column | Type | Meaning |
| --- | --- | --- |
| `id` | UUID, PK | Named workspace id. |
| `name` | TEXT | Display name (unique among named workspaces; enforced by the app). |
| `folders` | TEXT (JSON array of `workspaces.id`) | Folders in file-tree order, including currently unavailable ones. |
| `is_default` | BOOLEAN | The Default workspace. |
| `current` | BOOLEAN | The workspace the window shows now. |
| `created_at`, `last_opened_at` | DATETIME | Lifecycle. |

## `documents` — identity of a Markdown file

Created on first open. Identity = `(workspace_id, path)`; renaming a file outside the app does **not** move the
record (it becomes `missing` until explicitly relinked), so discussions never silently attach to another file.

| Column | Type | Meaning |
| --- | --- | --- |
| `id` | UUID, PK | Stable document id used by all other tables and the UI. |
| `workspace_id` | FK `workspaces.id` | Owning workspace. |
| `path` | TEXT | Normalized relative path (`/` separators, no `..`). Unique per workspace. |
| `default_session_id` | FK `agent_sessions.id`, nullable | Session new discussions on this document use by default (header "Document session"). |
| `last_sha256` | nullable | Hash of the file content most recently observed (open or watcher). |
| `missing` | BOOLEAN | File no longer exists at `path` (renamed/deleted outside the app). |
| `hidden` | BOOLEAN | Hidden from the *Recent* list (history kept). Toggled with `PUT /documents/{id}/hidden`. |
| `created_at`, `updated_at` | DATETIME | Record lifecycle. |

## `document_versions` — every content version seen

A row (and a snapshot file) is recorded whenever the app observes new bytes: on open, on a watcher change, after
an agent edit, or on preview apply. Needed to display the exact text a discussion was anchored to and to diff.

| Column | Type | Meaning |
| --- | --- | --- |
| `id` | UUID, PK | Version id (accepted by `GET /documents/{id}/diff?from=` as well as the hash). |
| `document_id` | FK `documents.id` | Document. |
| `sha256` | 64 hex | Content hash; unique per document. |
| `snapshot_ref` | TEXT | Path **relative to `<state_dir>/snapshots/`** of the exact bytes (`<document_id>/<sha256>.md`). |
| `git_branch` | nullable | Branch checked out when the version was seen (metadata only). |
| `git_commit` | nullable | HEAD commit when seen (metadata only; the file may have been uncommitted). |
| `source` | `observed` \| `preview_apply` \| `user_edit` \| `agent_edit` | How the version came to exist (`user_edit` = saved from the in-browser editor). |
| `created_at` | DATETIME | When first seen. |

## `agent_sessions` — provider conversations

An app-level record of an OpenCode/Codex conversation. `native_id` is the provider's own session id and is
only ever sent back to the same `provider`.

| Column | Type | Meaning |
| --- | --- | --- |
| `id` | UUID, PK | App session id (what the API and UI use). |
| `provider` | `opencode` \| `codex` | Provider adapter. |
| `native_id` | TEXT, nullable | Provider session id (`ses_…` for OpenCode, UUID thread id for Codex). `NULL` until the provider allocates it on the first turn. Unique per `(provider, native_id, workspace_id)`. |
| `workspace_id` | FK `workspaces.id` | Workspace the session was created for. |
| `display_name` | nullable | Title shown in the UI (e.g. `Wiki: docs/guide.md`). |
| `status` | see below | `uninitialized` (no native id yet) · `ready` (provider confirmed/used) · `missing` (provider no longer has it) · `unavailable` · `availability_unknown` (linked externally, not yet exercised). |
| `origin` | `app` \| `linked` \| `preview` | Created by the app, linked from the provider's list/by id, or an isolated preview session. |
| `model` | TEXT, nullable | Model override for app-driven turns in this session (`opencode run --model`, `codex exec -m`); NULL = provider default. Changed via `PUT /agent-sessions/{id}/model`; past messages are unaffected. |
| `variant` | TEXT, nullable | Reasoning effort / variant passed with the model (`--variant`, `model_reasoning_effort`). |
| `created_at`, `updated_at` | DATETIME | Lifecycle. |

## `threads` — a discussion anchored to a passage

The **original** anchor (`orig_*`) is immutable: the version and exact text the user selected. The **current**
anchor (`cur_*`) is where the discussion is attached now; it changes only through explicit manual reanchoring
(`PUT /threads/{id}/anchor`). Automatic resolution against the live document (attached/moved/ambiguous/orphaned)
is computed at read time and does not overwrite `cur_*`.

| Column | Type | Meaning |
| --- | --- | --- |
| `id` | UUID, PK | Thread id. |
| `document_id` | FK `documents.id` | Document the passage belongs to. |
| `orig_version_sha256` | 64 hex | Content hash when the selection was made. |
| `orig_quote` | TEXT | Exact selected rendered text. |
| `orig_prefix`, `orig_suffix` | TEXT | Up to 40 code units of surrounding model text, for disambiguation. |
| `orig_start`, `orig_end` | INTEGER | UTF-16 offsets `[start, end)` in the text model of that version. |
| `orig_heading` | nullable | Nearest preceding heading text. |
| `cur_version_sha256`, `cur_quote`, `cur_prefix`, `cur_suffix`, `cur_start`, `cur_end`, `cur_heading` | as above | Current anchor (equal to `orig_*` until manually reanchored). |
| `anchor_state` | `attached` \| `moved` \| `ambiguous` \| `orphaned` \| `document` \| `page` | Last stored resolution state (the API recomputes it for text anchors on every read). `document`: about the whole document; `page`: about a page, slide, area or picture (see `target_json`); neither is re-anchored. |
| `diff_json` | JSON, nullable | Set when the discussion was started as a comment in the diff review: `{base, target, side, line_no, line_text, hunk, anchored}`. |
| `target_json` | JSON, nullable | For `page` discussions: `{kind: text\|page\|area\|image, page, unit: page\|slide, rect: [x,y,w,h] fractions, label, attachments: [file names]}`. The images live in `<state_dir>/snapshots/attachments/<thread id>/` (in backups; removed with the document's history) and are attached to every agent turn of the discussion. |
| `last_session_id` | FK `agent_sessions.id`, nullable | Session the most recent turn used; replies default to it. |
| `created_at`, `updated_at` | DATETIME | Lifecycle (`updated_at` moves on reply/reanchor). |

## `messages` — the Q&A transcript

One row per user question and per agent answer. The agent row is created immediately with `status = queued`
and filled in when its job finishes, so a failed/cancelled turn still shows the question.

| Column | Type | Meaning |
| --- | --- | --- |
| `id` | UUID, PK | Message id. |
| `thread_id` | FK `threads.id` | Discussion. |
| `session_id` | FK `agent_sessions.id`, nullable | Session actually used for this turn (may differ per message). |
| `role` | `user` \| `agent` \| `system` | Author. |
| `content` | TEXT | Full text (Markdown for agent answers). For failed turns: the error message. |
| `status` | `queued` \| `running` \| `completed` \| `failed` \| `cancelled` \| `interrupted` | Mirrors the job for agent messages; `completed` for user messages. |
| `job_id` | UUID, nullable (soft ref → `jobs.id`) | The agent run that produced/produces this message. |
| `created_at` | DATETIME | Order within the thread. |

## `locks` — user-declared read-only paths

A lock makes a file, a folder (recursively) or the whole workspace (`path = ""`) read-only **for the app**: preview
Apply, relink and history deletion return 423 `PATH_LOCKED`; app-driven agent turns are told the path is locked
and Codex runs with the `read-only` sandbox; a change that still happens is reported as a `lock_violation` job
event. The user's terminal is never restricted.

| Column | Type | Meaning |
| --- | --- | --- |
| `id` | UUID, PK | Lock id. |
| `workspace_id` | FK `workspaces.id` | Workspace. |
| `path` | TEXT | Normalized relative path; `""` = whole workspace. Unique per workspace. |
| `is_dir` | BOOLEAN | Folder lock (covers everything below) vs single file. |
| `reason` | TEXT, nullable | Optional note shown in tooltips and in the agent prompt. |
| `created_at` | DATETIME | When locked. |

## Useful queries

```sql
-- all Q&A, newest first
SELECT d.path, t.cur_quote, m.role, m.status, m.content, m.created_at
FROM messages m JOIN threads t ON t.id = m.thread_id JOIN documents d ON d.id = t.document_id
ORDER BY m.created_at DESC;

-- which provider session answered what
SELECT m.created_at, s.provider, s.native_id, substr(m.content, 1, 80)
FROM messages m JOIN agent_sessions s ON s.id = m.session_id WHERE m.role = 'agent';

-- the exact text a discussion was anchored to (then read snapshots/<document_id>/<sha>.md)
SELECT document_id, orig_version_sha256, orig_quote FROM threads WHERE id = ?;
```
